# Review checklist — storage and sync changes

Answer each question for the diff. A "no" or "unsure" is a finding.

**Durability**
- Does every database mutation run inside a transaction, and does a multi-step update (read-modify-write, delete-then-insert) happen in **one** transaction?
- Can an app kill between any two lines leave the data half-written?
- Is an id generated by the client for anything the server must dedupe?

**Source of truth**
- Does any code path overwrite or delete local user data because the server returned something different? If yes, is it a documented exception that only applies when the server is strictly ahead?
- Does a "fetch" ever replace local state wholesale (`addAll`/clear + insert) instead of merging by a stable key? What happens if two triggers (start-up and a refresh, a day rollover) run it back to back?
- Is the key used to match a local record to a server record stable, or derived from something that can change?

**Never block on the network**
- Does a screen or calculation `await` a network call to render? It must render from the local store and update when the response arrives.
- Is the only connectivity requirement something that truly cannot work offline?

**Outbox**
- Is the write enqueued (not sent) from the user action? Is the payload self-contained?
- Does the handler return the right outcome for 2xx, partial acceptance, network/5xx, and 4xx?
- Can an entry be removed before the server confirmed it?

**Logout and cleanup**
- Does logout still clear local state when the server call fails?
- Does anything in logout or cleanup delete pending outbox entries?

**Isolates**
- Does an isolate write to the main database file? It should use its own.
- Are preferences reloaded after another isolate changed them?

**Decimals**
- Do quantities that need precision pass through `double` anywhere between input, storage, sending and display?
